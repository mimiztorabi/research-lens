# Product brief: Research Lens

<!-- This file frames the product opportunity for a portfolio reviewer. -->

## One-line concept
Research Lens helps a researcher assemble selected sources into a concise, cited brief they can inspect and refine.

## Problem
People preparing a recommendation or strategy document often spend hours moving between tabs, notes, and drafts. Generic AI summaries can be fast, but they may blur source boundaries and make it difficult to verify a claim.

## Target user
**Primary:** a product manager preparing a decision brief from a limited set of approved research sources.

**Secondary:** a UX researcher or product-operations partner who needs to audit how a draft represents the supplied evidence.

## Value proposition
Turn a bounded source set into a reviewable starting point, while keeping every key claim connected to the material that supports it.

## Product principles
1. **Bound the evidence.** The assistant uses only selected sources in the concept flow.
2. **Make verification easy.** Claims should expose their source references.
3. **Expose uncertainty.** Missing, conflicting, and weak evidence must be visible.
4. **Keep the human accountable.** The user reviews, edits, and decides; the tool does not make decisions for them.

## Success hypothesis
If researchers can create an inspectable first draft from a bounded source set, then they will spend less time assembling a brief and more time evaluating evidence and making a decision.

## Product strategy and trade-offs

Research Lens starts with a narrow, high-trust use case: drafting from a small, user-approved set of sources. This sacrifices the convenience of open web search and automatic ingestion in exchange for a clearer evidence boundary and a more believable portfolio prototype.

| Decision | Benefit | Trade-off to communicate |
| --- | --- | --- |
| Bounded source set | Makes provenance easier to inspect. | Users must prepare sources before starting. |
| Cited draft, not recommendation | Supports review without overstating AI authority. | The user still has to form the final point of view. |
| Static prototype | Safe to share publicly and simple to understand. | It demonstrates the interaction, not real model quality. |
